# vendor.lineage.livedisplay-service.emerald (prebuilt)

Our LiveDisplay service (`livedisplay/service.cpp`): color profiles, picture adjustment (hue,
saturation, intensity, contrast), color calibration (red, green, blue) and reading mode, applied
by the display pipeline (the color matrix of CCORR and the global contrast of COLOR, through the
stock MediaTek PQ HAL) instead of a SurfaceFlinger color matrix, which makes the MTK HWC compose
every frame on the GPU. lineage-sdk picks the four vendor.lineage.livedisplay services up because
they are declared in the vintf fragment; the framework needs no change.

patch-images.py adds it to vendor.img with `livedisplay/`'s .rc and vintf fragment, its domain in
vendor_sepolicy.cil (a hal_lineage_livedisplay server and a hal_mtk_pq client; the LiveDisplay
attributes, service type and clients come from the LineageOS system_ext policy), its file context
and the property that keeps the display mode (persist.vendor.livedisplay.mode). The vendor image is
the stock one, so the binary is needed before the build starts and is kept here.

Built 2026-10-29 by hand, without a soong analysis (scripts/livedisplay/build.sh in the build
notes): the interface code generated by out/host aidl from the frozen vendor.lineage.livedisplay V1
api and linked statically, compiled with the vendor cflags of the clean-2.10 graph and linked with
its link command. A rebuild gives the same code and data; only the build id differs (it hashes the
debug info, which holds the build directory).

  user checked the profiles, the RGB sliders, reading mode and the picture adjustment sliders, and
  that the settings stay after the screen goes off and on.
