# System-side MediaTek blobs from stock OS3.0.305.0.WNFMIXM system_ext (vendor-side files are not
# listed: vendor, vendor_dlkm, odm_dlkm and system_dlkm ship as the stock images).
# Selection as LineageOS motorola/mt6768-common and xelex/Q25, without the video call service (see IMS).
# Not taken: the stock audio parameter parser (system_ext/bin/hw/android.hardware.audio.parameter_parser.service).
# It links android.hardware.audio.core-V3 while LineageOS 23.2 and 24.0 build V4, and audioserver only uses it when
# ro.audio.ihaladaptervendorextension_enabled=true, which stock sets in system/build.prop (not ours).

# IMS
# Not taken: system_ext/priv-app/MtkTelephonyAssist (HyperOS build: DataStateController calls
# android.telephony.TelephonyBaseUtilsStub, a HyperOS framework class -> com.android.phone crash loop on 2026-10-13).
# mediatek-res declares the MediaTek protected broadcasts (com.mediatek.common.carrierexpress.* ...); without it
# Android 16 kills com.mediatek.ims: WfcHandler registers a receiver without RECEIVER_EXPORTED (2026-10-13).
# Not taken on 24.0 (clean-2): the video call service (vtservice, libmtk_vt_service, libimsma*, libsink, libsource,
# libsignal, libvt_avsync, libcomutils). libsink calls the Android 16 AudioTrack constructor; Android 17 added a
# codecProvenance argument and an std::string member, so the symbol is gone and AudioTrack is bigger than the
# blob allocates - no safe shim. Only vtservice, the video call (ViLTE) media service, uses that chain; init starts
# it only with persist.vendor.vilte_support=1. The ImsService JNI wrapper libmtk_vt_wrapper loads without it but
# blocks waiting for it while ViLTE / ViWiFi are on, so device.mk turns both off.
